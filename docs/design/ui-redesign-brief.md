# Design brief — Talk Feedback (Packt workshop), UI redesign

Product: workshop talk-feedback app. Users: attendees (phone, 30 seconds, leave a rating) and the speaker/organiser (desktop, read results). Job: make leaving feedback effortless and make results instantly legible. Identity: five original native-SVG "Grok Bot" mascots (ink #101516, green #00C972, pink #FF309B, violet #9159FE, red #FF263C) = the logo/brand. Current state: pale-lavender page + single cobalt accent; generic, flat, repetitive thin-border cards, weak hierarchy, CSS-only bars, three overlapping stylesheets (globals.css legacy `.site-*` rules + loop.css + bots.css).

## What the references teach (synthesis)
- Impeccable (59 deterministic checks): the "AI slop" tells to avoid = purple/blue gradient text and washes, side-stripe card borders, nested cards, identical rounded cards everywhere, gray text on coloured bg, bounce/elastic easing, glow/glassmorphism, pure #000/#fff or untinted grays, overused default fonts, tracked ALL-CAPS eyebrow above every heading, icon tile above every heading, tiny type, cramped padding, small touch targets (<44px), skipped heading levels, line length >75ch, low contrast, clipped/overflowing labels. Fix with: clear hierarchy (ONE primary action per screen), tinted neutrals, a real type scale, consistent spacing scale, state design (hover/focus/active/disabled/loading/empty/error), and design-token documentation (DESIGN.md).
- frontend-design (Anthropic): commit to a specific point of view from the subject matter (here: bots, loop, workshop); "spend boldness in one place" — one memorable element, everything else quiet and disciplined; typography carries personality; non-triggered motion sparing (one orchestrated load moment max); quality floor = responsive, visible focus, reduced-motion respected, accessible.
- UI UX Pro Max: priority order accessibility (AA contrast, focus, labels) > touch (>=44px targets) > performance > layout/responsive > type & colour > motion (150–300 ms, ease-out, transform/opacity only) > forms/feedback > charts (label directly, don't rely on colour alone, give a table alternative).
- build-dashboard (Anthropic KW plugin): KPI strip (2–4 numbers) → primary chart (largest area) → secondary chart/detail → sortable-looking detail table; filters/selection top; consistent number formatting; loading/empty/error states.
- Open Design / Superdesign: design-system-first — decide tokens (colour, type, spacing, radius, elevation) once, then compose screens from them; refine with screenshots at 390/768/1440.

## Direction: "Loop Studio"
One memorable thing: the loop stage on the home page (the five bots circling Build → Listen → Improve) — keep BotBackdrop/WorkshopMascot behaviour intact. Everything else calm and precise.

Tokens (define as CSS variables in ONE place, `@theme`/`:root` in globals.css; map shadcn vars to them):
- Ink #101516 (text/primary action), Ink-2 #3E4748 (secondary text, >=7:1 on paper), Paper #F5F6F2 (canvas, tinted not white), Surface #FFFFFF, Line #DADFD8, Focus ring = ink 3px offset 3px + white inner.
- Bot accents (used as FILLS/marks only; text on them is ink): Green #00C972 = primary highlight/positive/selected, Pink #FF309B, Violet #9159FE, Red #FF263C (error/low ratings only via text-safe darker variants for text, e.g. #B3001B), keep AA (>=4.5:1 body, >=3:1 UI/graphics).
- Chart palette: categorical per talk = the four bot colours + ink (always with direct value labels, never colour-only); rating distribution = sequential ramp low→high (red→neutral→green) with count labels.
- Type: Manrope (already self-hosted variable font, no new network fonts). Scale 12/14/16/18/24/32/48/72 with tight tracking on display (−0.03em), weight 800 for display/numerals, 600 for labels, 400–500 body, `font-variant-numeric: tabular-nums` for all numbers. Body 16px mobile-first, max line 65ch. No ALL-CAPS eyebrows.
- Spacing 4-pt scale (4/8/12/16/24/32/48/72/96); radii: 8 controls, 16 panels, 999 pills; elevation: at most 2 levels, soft tinted shadow (ink @ 6–10%), no glows/gradients.
- Motion: tokens 150/240 ms, ease-out `cubic-bezier(.2,.7,.2,1)`; transform/opacity only; one staggered reveal on the home hero; chart bars grow once; everything off under prefers-reduced-motion.

Layout/density:
- Shell: slim sticky-less header (Grok Bot mark = the black blob with two eyes as inline SVG, wordmark "Talk Feedback"), pill nav with aria-current, mobile nav that never wraps badly at 320–390; footer minimal.
- Home: asymmetric hero (display headline left, loop stage right), one primary CTA + one secondary; below, a 3-step strip that reads as a sequence (numbers are legitimate here) with real copy, plus a small "what you will see in results" preview using the same chart styles (no fake data presented as real: label it as an example, or omit).
- Feedback: single focused form card (max 640px) + quiet side panel; large 5-star control (>=48px targets, hover/focus/checked clearly different, selected label text "4 of 5 — Good" etc.), inline validation, comment OPTIONAL (keep wording "optional"), rating REQUIRED, character counter, success state that celebrates briefly and links to results, error state with retry, disabled/submitting state.
- Results: dashboard per build-dashboard: KPI strip (responses, talks, overall average, top-rated talk) → left: "Across the workshop" ranked horizontal bars (shadcn ChartContainer/recharts if tests allow, else CSS) with value labels and fixed 0–5 scale, clickable to select a talk → right: selected-talk detail (big average, % rated 4–5, distribution chart with counts, written feedback list as quotes without name) → full table. Skeleton, empty ("No feedback yet" + CTA), error (alert + retry), stale and refreshing states all designed. No nested cards; separate by spacing, hairlines and surface tone.

Hard constraints: behaviour unchanged (comment optional, rating required, API routes untouched), existing vitest + e2e selectors/ARIA names keep passing (change a test only if it asserts purely cosmetic class names, and list it), no heavy new deps (recharts and shadcn chart already installed), no Itaú/personal data, no edits in .github/, no git commit/push (the caller commits). Do not use `sed` for edits; use normal patch editing.
